# Project brief — Sequence Desk

- Status: fictional public design study; no affiliation with a real software product.
- Goal: let a small launch team understand and unblock a release without learning project-management jargon.
- Audience: non-developer founders and cross-functional vibe-coding teams.
- Primary job: identify the next blocking decision and assign a clear owner.
- Primary action: resolve one launch blocker from the decision queue.
- Content priority: release health → next decision → dependency sequence → evidence → activity.
- Brand: calm operational clarity, editorial confidence, no productivity theatre.
- Anti-direction: generic purple SaaS, bento marketing cards, fake analytics, dense enterprise sidebar, animation on every widget.
- Signature idea: a “decision lens” turns a noisy task board into one explainable chain: signal → choice → owner → proof.
- Constraints: native HTML/CSS/JS, no backend and no transmission; interactions must be reversible and keyboard reachable.
- CTQs: Can a non-developer explain why the release is blocked? Can they change scenario and resolve a decision with clear feedback? Is empty/success state understandable without color?

## Reference principles

- Product proof should be embodied in a working interface rather than claims.
- Dense information earns hierarchy through typography and rules, not nested cards.
- State changes use continuity and explicit text; motion never replaces status.
