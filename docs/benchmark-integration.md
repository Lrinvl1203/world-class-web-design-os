# Benchmark integration record — 2026-08-09

This record maps useful public-repository advantages into this OS without replacing its 17-skill architecture.

| Observed advantage | Adopted implementation | Boundary |
|---|---|---|
| Searchable style/industry knowledge | `web-design-os search` over the evidence-graded Design DNA atlas | Search returns principles and misuse warnings, not a style recipe to copy |
| Low-context skill routing | `web-design-os route` and a three-specialist phase budget | The orchestrator remains governing; keyword output is advisory |
| One-command setup | `web-design-os setup` project-context scaffold | Existing context is never overwritten |
| Cross-agent packaging | `web-design-os install` target mapping | Codex remains canonical; compatibility is filesystem-level, not a guarantee of identical runtimes |
| Asset acquisition discipline | design-discovery asset protocol | Unknown rights remain an explicit dependency |
| Product-task depth | interaction edge-case matrix | Apply relevant states; do not inflate simple pages |
| Skill eval fixtures | bilingual positive/negative routing cases plus evolution unit tests | Evals test routing and governance, not subjective design quality |
| Engineering/browser verification | Playwright, axe, console, overflow, reduced-motion gates in CI | Field Core Web Vitals and human usability still require external evidence |
| Continuous inspiration capture | daily official-API/RSS/manual signal pipeline | No logged-in scraping, copied content, silent skill edits, direct push, or self-merge |

The OS retains its existing differentiators: design intent before tools, builder/critic separation, reference evidence levels, dedicated responsive recomposition, hard release gates, honest Web Design OS scoring, and validated learning proposals.
